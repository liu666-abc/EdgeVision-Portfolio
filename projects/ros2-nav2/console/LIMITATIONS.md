# Nav2 Mission Console 验证与限制

最后更新：2026-10-25

本文记录控制台已经验证的能力、尚未验证的内容、已知限制，以及当前证据无法支持的结论。

## 已验证

- mock 模式已覆盖建图/导航模式切换、低速遥控、安全停止、安全确认，以及 Nav2 不可用时
  禁用导航目标。
- 浏览器 smoke test 已覆盖 `1440x1000` 桌面视口和 `390x844` 手机视口，包括 WebSocket
  连接、Canvas 绘制、页面溢出和浏览器控制台异常检查。
- 命令接口会拒绝跨站请求、非 JSON 请求，以及未明确确认安全的运动命令。
- 2026-10-25 的真实 ROS 栈静止验收通过：地图与雷达实时更新、`map -> laser` TF、
  地图保存、二进制地图绘制和 `ACTION SERVER READY`。
- 控制台已显示真实地图、机器人位姿、雷达扫描和 Nav2 状态；本轮未发送导航目标，未移动底盘。
- 启动脚本通过 FastDDS 预热参与者规避已复现的首参与者异常，过程记录见控制台 README。

## 尚未验证

- 2026-10-25 没有通过控制台发送真实导航目标。
- 尚未在完整真实栈上复验
  `建图 -> 保存地图 -> 切换到 Nav2 -> 设置初始位姿 -> 发送目标 -> 安全停止` 全流程。
- 最新一轮验收没有通过控制台执行地面导航、动态绕障和故障恢复。
- 控制台尚无长时间浏览器或服务端 soak test。
- 尚未测试多客户端并发和高延迟网络。
- 浏览器验证仅覆盖已测试的 Chromium/Edge 版本和视口，Firefox、Safari 和其他移动浏览器未验证。

## 已知限制

- 控制台没有用户登录和 TLS，只应部署在受控机器人局域网，不能直接暴露到公网。
- WebSocket 地图通道在 revision 变化时发送整张 OccupancyGrid 二进制包；虽然限频，但尚未实现
  分块或瓦片增量传输。
- 控制台状态和事件历史保存在运行进程中，服务端重启后当前会话状态会清空。
- 真实操作依赖配置后的 ROS 话题、action 名称、设备别名、板端绝对路径和厂家 launch 文件。
- 相机画面仍使用独立 MJPEG 流，不由 WebSocket 服务端编码。
- 安全确认和零速命令属于软件控制，不是独立硬件急停，也不构成功能安全认证。
- A3 语义标记和下视相机贴线尚未接入本控制台。

## 后续优先级

1. 每次 RDK 重启后重新执行静止联调。
2. 在用户明确确认场地清空、手在电机开关旁后，验证完整建图到导航地面流程。
3. 增加 WebSocket 服务端和浏览器的断线重连、长时间 soak test。
4. 在大地图上测量传输耗时，再决定是否实现分块增量更新。
5. 只有部署超出可信局域网范围时，才增加登录和 TLS。
6. 补充部署打包和简明故障恢复手册。

## 不应宣称

- “生产级”或“已通过功能安全认证”。
- “已通过控制台完成真实建图和导航全流程验证”。
- “二进制地图增量协议”。当前实现是在地图 revision 变化时发送整张网格。
- “独立急停”。运动安全仍依赖机器人、网络、服务进程和现场人员操作。
- “语义导航已完成”。A3 语义标记仍属于后续工作。
