# 2026-10-22 双路视频、双检测实例测试（污染记录）

> **污染提示：** 本测试期间发现一个上次 MOT 评估遗留的视频源进程仍在运行。
> 本文件保留为排查过程记录，不作为双路调度性能的最终结论。
> 干净复测见 `../../2026-10-23_dual-stream10/README.md`。
>
> **结论等级：INVALID。** 14.768 Hz 不能归因于 BPU/CPU 饱和，也不能作为双路达标证据。

## 目的

在同一个 RDK X5 上同时运行两路 25 FPS 视频和两个 YOLOv8n INT8 检测实例，
观察第二路加入后的话题频率、资源占用和调度退化。

## 配置

- ROS domain：`59`。
- A 路：
  - 视频：OpenCV `vtest.avi`；
  - 分辨率：`768x576`；
  - 输入：`/camera_a/color/image_raw`；
  - 输出：`/evi/detections_a`；
  - 节点：`detector_a`。
- B 路：
  - 视频：Intel `one-by-one-person-detection.mp4`；
  - 分辨率：`768x432`；
  - 输入：`/camera_b/color/image_raw`；
  - 输出：`/evi/detections_b`；
  - 节点：`detector_b`。
- 两路视频源均强制 `25 FPS` 循环。
- 两路检测器均启用 Kalman + IoU 跟踪。
- 上位机显示 A 路。
- 不启动底盘、雷达、STM32。

注意：两路 CSV 的实际行数不对应严格 5 分钟，因为测试结束后为了测量话题频率又继续运行了一段时间。
表中数值用于单帧处理时间分析，不用于计算 5 分钟实际帧率。

## 判读

- A 路在双实例条件下仍保持约 25 FPS。
- B 路处理器单帧 `total_ms` 仍低于 40 ms，但实际输出只有约 14.8 FPS。
- 说明 B 路退化主要来自消息排队、调度或共享路径，而不是单帧计算时间本身。
- 资源总量仍未饱和：CPU 约 42%、BPU 约 15%，温度约 52 °C。
- 因此当前瓶颈不能归因于“CPU 或 BPU 算力已经用尽”。

## 未查明

以下原因尚未隔离：

- 两个检测线程的 CPU 调度和亲和性；
- DDS 接收队列与 QoS；
- BPU 多实例共享路径；
- 两个 Python 视频源进程的调度；
- 上位机只订阅 A 路但仍占用共享 CPU。

不能把 B 路降低简单归因于某单一原因。
